# Day 12 — Production Readiness Audit

**Project:** Zyngram Complete Franchise System (Day 10) + Employee Management (Day 11)  
**Audit date:** 2026-10-07  
**Scope:** Current source, local configuration, existing documentation, focused build/syntax checks, available backend unit tests, and local API smoke checks.

## Executive verdict

**NOT READY for production deployment.** The existing application is a useful local/demo foundation, but several required production workflows are missing or trust client-controlled values. Authentication, data isolation, financial integrity, durable database operations, and deployment evidence must be addressed before using real customers, employee records, or money.

This is a source-level readiness assessment, not a penetration test, external dependency vulnerability scan, production migration rehearsal, or live deployment certification. The Day 10 security document reports previous test results, but this audit did not treat those claims as independently verified.

## Priority blockers

### P0 — Fix before any production or real financial/customer data

1. **Order pricing/provider production controls are still required.** The generic order create/read/confirm APIs require HQ Admin; create validates active customer/service, positive finite amount, and location ownership, while Mobile Recharge uses separate authenticated customer and HQ Admin APIs. Recharge requests now require unique idempotency keys, and local duplicate retries are rejected. Approved service pricing and production provider integration/verification remain outstanding.
2. **Financial rates still require business approval.** Runtime calculation now uses effective active database rules; the version-9 seed preserves prior demo rates and is not an approved production schedule. Obtain authorized rates before production, then validate a real attributed order through wallet settlement.
3. **Inconsistent authorization and tenant isolation.** The reviewed high-risk order, location, employee, document, and commission endpoints now have role/owner checks; authentication also revalidates the active account and derives franchise-owner scope from current database assignments. Other user, franchise, report, leave, target, and document operations still need a full route-by-route authorization matrix and cross-tenant API suite.
4. **Unsafe production authentication defaults.** The backend seeds a known demo administrator for local development. Production startup must fail closed unless a strong secret and an intentional secure administrator bootstrap are configured. See [backend/server.js](./backend/server.js) near configuration and database seeding; setup instructions are in [README.md](./README.md).
5. **Employee document access policy.** Employee document upload/list/download/delete routes now restrict access to HQ Admin or Franchise Owner and verify the employee/document's franchise against server-derived owner assignments. Cross-franchise owner and employee self-service behavior still need integration tests against real owner fixtures.

### P1 — Required before production rollout

- Configure CORS for the deployed frontend origin; add security headers, API rate limits, request-size/content validation, production error handling, and monitoring.
- Finish converting the legacy startup schema and user-code column alteration into versioned forward/rollback migrations; define production database/storage, backup/restore, and sanitized migration rehearsal.
- Integrate an authorized telecom sandbox/provider for real Mobile Recharge processing; retain the local simulation label until provider results are verified. Never accept customer-selected franchise or commission values.
- Keep order confirmation, attribution snapshot, commission calculation, and ledger writes transactional; the recharge transaction is currently covered locally, but production-scale retry/concurrency and wallet settlement rehearsal remain outstanding.
- Document deploy, secrets, backups, rollback, and recovery procedures; the local database-backed health/readiness endpoint is present and verified.
- Add integration/API tests for authorization, cross-franchise access, inactive users, document downloads, tampering, duplicate orders/commissions, and production migrations.
- Review browser token storage/session lifecycle and minimize access to sensitive records in reports and employee APIs.
